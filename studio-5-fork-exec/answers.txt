Each execution has a different PID because the operating system
assigns a unique process identifier to each new process.

Exercise 2:

Process PID: 986
Process PID: 987

The program prints twice because fork() creates a child process.
Both the parent and child execute the code after fork(), and each
process has its own unique PID.
Exercise 3:

fork() returns 0 in the child process and the child's PID
(a positive integer) in the parent process.

If fork() fails, it returns -1 in the parent process,
and no child process is created.
Exercise 4:

Parent process PID: 1131
Child process PID: 1132

The parent process receives the child's PID as the return value
of fork(), while the child receives 0. This allows the program
to identify which process is the parent and which is the child.
Exercise 5:

Parent process PID: 1229
[Terminal prompt appeared]
Child process PID: 1230

The parent prints its PID and terminates immediately without
waiting for the child. The terminal prompt appears before the
child prints its PID because the child is sleeping for 3 seconds.

This is expected because the parent and child execute independently,
but it is undesirable when the parent needs the child to finish first.

Exercise 6:

Child process PID: 1337
Parent process PID: 1336

Unlike Exercise 5, the parent now waits for the child to finish
before printing its own PID. The child sleeps for 3 seconds,
prints its PID, and terminates. Then the parent resumes execution
after waitpid() and prints its PID.

The terminal prompt appears only after both processes finish.
